# chore: retire the delivery-doc skill and end the delivery window on Dec 2

**PR:** [#116](https://github.com/lioramilbaum/lioramilbaum.github.io/pull/116) · **Opened:** 2026-11-16 · **Hackathon:** Day 9 of the Qodo Software Factory hackathon, [Set up quality gates](https://github.com/orgs/qodo-hackathon/discussions/11): the delivery process that Day 9's gate shaped is simplified, now that the workflow is its only writer.

## Why

_From the PR description (author-written)._

Since #106, the Delivery doc workflow is the only writer of delivery docs and docs PRs. Since #113, it also brings the fork's `main` up to date before it pushes. The delivery-doc skill had become a thin copy of rules that already live elsewhere:
- **Its Part B** (after a merge) was a few `gh` commands for reading the workflow's run and dispatching it again.
- **Its Part A** (before a merge) restated rule 9, and the generic `qodo-review-resolver` skill does that work. #106's and #113's findings were cleared with it.

Keeping the skill meant keeping a second copy of the process in sync. Separately, the delivery window now ends on the hackathon's last day, 2026-12-02, instead of 2026-12-12.

## How

_From the PR description (author-written)._

- The skill is deleted. What it held that AGENTS.md lacked moved there:
  - **Rule 6** has the steps for a red run:
    1. Find the run by its merge commit.
    2. Read its last `skipped:`, `error:` or `docs PR:` line.
    3. Fix the cause.
    4. Dispatch once.

    A repeat failure, or a cause outside the repo (a diverged fork `main`, a refused push, a token's permissions, a head Qodo never reviewed), goes to the owner. The read-only `scripts/generate-delivery.sh --pr N --check` stays.
  - **Rule 9 and the Workflow section** say that Qodo findings are cleared with `qodo-review-resolver`, under rule 9's approval rules, and that a docs PR is read-only for the agent: it reports each finding to the owner.
- Every reference to the skill is reworded to name the Delivery doc workflow. That covers the PR template, the agent run, the agent's prompt, and comments and messages in `generate-delivery.sh`, `qodo-status.sh` and `delivery-run.sh`. The generated delivery-doc sentence now reads "The Delivery doc workflow never posts to the hackathon discussions." Existing docs keep their old wording.
- The window ends at `2026-12-02T23:00:00Z`, the end of Dec 2 CET. `scripts/check-delivery.sh` holds the one cutoff. `delivery-run.sh` reads its result, so it needs no change.

## What

_From the PR description (author-written)._

- Deleted: `.claude/skills/delivery-doc/SKILL.md`. `.claude/` stays excluded from the site and guarded for the agent run.
- `AGENTS.md`: Setup, rule 6 (Where, the red-run steps, the end date), rule 7 (the end date), rule 9 (Where, `qodo-review-resolver`), and the Workflow section.
- `scripts/check-delivery.sh`: `cutoff=2026-12-02T23:00:00Z`.
- `scripts/test-delivery.sh`: the window cases, the frozen clock and dr7 move to the new instant. With the cutoff left at 2026-12-12, four of them fail: the three `cut.` cases and dr7.
- Wording only: `.github/pull_request_template.md`, `scripts/agent-run.sh`, `scripts/agent/prompt.md`, `scripts/generate-delivery.sh`, `scripts/qodo-status.sh`, `scripts/delivery-run.sh`.
