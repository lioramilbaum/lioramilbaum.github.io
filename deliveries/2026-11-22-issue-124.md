# fix: hide the followers line for octal, hex, signed and underscored counts

**PR:** [#125](https://github.com/lioramilbaum/lioramilbaum.github.io/pull/125) · **Opened:** 2026-11-22 · **Hackathon:** [Day 12: Give your factory the full picture](https://github.com/orgs/qodo-hackathon/discussions/14) ([post](https://github.com/qodo-hackathon/software-factory-hackathon/discussions/14#discussioncomment-19820008)): Qodo found this bug while checking PR #118 against issue #28.

## Why

_From the PR description (author-written)._

Issue #124: the homepage's followers line (PR #118, issue #28) could show a number the owner never wrote. Jekyll parses `_data/linkedin.yml` before the template sees it, and YAML 1.1 reads `followers: 012` as octal 10, `0x1A` as 26, `+5` as 5 and `1_000` as 1000. The template's check compared the parsed number with itself printed back, so all four passed, and the homepage showed `10 LinkedIn followers` for `012`. Qodo's re-review of the merged PR #118 found it (finding 18078da8, "Visitors can see the wrong follower count", status `detected_after_merge`), while checking ticket #28's criteria for the hackathon's Day 12 challenge. The bug was reproduced in the pinned build image (Jekyll 3.10.0, SafeYAML). The live value, `29572`, was never affected.

## How

_From the PR description (author-written)._

- Liquid only sees the parsed value, so the template now also reads the raw text of the data file with `{% include_relative _data/linkedin.yml %}`. The line shows only if exactly one line starts with `followers:` and its value is the parsed number written plainly: `29572`, `"29572"` or `'29572'`.
- The check runs inside the Pages build itself (`jekyll-build-pages`), so it protects the deployed site, not only CI. It needs no plugin and no Gemfile (AGENTS.md rule 4), and the data format stays the same.
- It fails closed (AGENTS.md rule 11): any other spelling, a duplicate `followers:` key, a trailing `# comment`, or an indented key hides the line, and `check-site.sh` then fails on the missing line in CI. The raw read sits inside `{% if li %}`, so a missing data file still hides the line rather than breaking the build.
- Rejected: a raw-text check in `check-site.sh` or `build-site.sh`, because the deploy runs neither, so the live page would still show the wrong number. Also rejected: requiring quoted values, because it would break the plain `29572` the owner writes today.

## What

_From the PR description (author-written)._

- `_layouts/home.html`: the followers guard also requires the raw `followers:` line to match the parsed number. A Liquid comment says why, and says that `include_relative` resolves from the page's directory, so only a root page can use this layout.
- `scripts/test-site.sh`: 11 new cases, 26 in all, each one a full build checked by the real `check-site.sh`:
  - Hidden: the four required cases (`012`, `0x1A`, `+5`, `1_000`), a duplicate key, a trailing comment and an indented key.
  - Shown: single quotes, CRLF line endings, a `followers_x:` key beside a valid `followers:`, and a file with no trailing newline (a new optional `nonl` argument to `case_run`).
- `_data/linkedin.yml`: comment only. The value is plain decimal digits with no leading zero, alone on its line, and the file is read as Liquid too, so it must not contain Liquid tags. The values are unchanged.

## Limitations

_From the PR description (author-written)._

- Two spellings that are valid YAML now hide the line: a trailing `# comment` on the `followers:` line, and a duplicate key. Both are deliberate (fail closed) and tested.
- Reading the data file as Liquid adds two ways to break the build loudly: Liquid tag markers inside `_data/linkedin.yml`, and renaming the file to `.yaml` or `.json` while `site.data.linkedin` still exists. Neither shows a wrong number (AGENTS.md rule 11). The data file's comment warns about the first.
- The `include_relative` read works only for a page at the repo root. README.md is the only `layout: home` page today, and the layout comment says so.
- Red CI run (AGENTS.md rule 8): [run 45077327593](https://github.com/lioramilbaum/lioramilbaum.github.io/actions/runs/45077327593) on the deliberately broken revision 28a72ca (the new cases without the layout change) failed at "Test the LinkedIn followers line": the octal, hex, plus-signed and underscored cases, and the duplicate followers key, commented followers line and indented followers line cases, reported `check-site.sh exited 0, not 1`.
