## Why

_From the PR description (author-written)._

Day 8 of the Qodo Software Factory hackathon ([discussion #10](https://github.com/orgs/qodo-hackathon/discussions/10)) asks for a small task to be implemented, left uncommitted, and reviewed with Qodo's local review before any commit. The task was #76, now [PR #101](https://github.com/lioramilbaum/lioramilbaum.github.io/pull/101). The results are posted at [the discussion comment](https://github.com/qodo-hackathon/software-factory-hackathon/discussions/10#discussioncomment-19620358). Issue #100's last criterion is that the website lists the submission.

## How

_From the PR description (author-written)._

This follows the same pattern as Days 6 and 7 (#83, #98): the page entry, an exact-URL assertion in `check-site.sh`, and `check-links.sh`'s time budget. The link uses the repo form, because `check-links.sh`'s comment lookup reads owner/repo from the URL. Day 8 brings the jobs to 22 (14 links and 8 comment lookups), and the old cap of 10 no longer fits:
- **Cap 10:** three batches, a worst case of 66 + 198 + 198 = 462 s, past the step's 5-minute timeout.
- **Cap 12:** batch 1 is 12 plain links (at most 66 s) and batch 2 is 2 links plus 8 lookups (at most 198 s). The worst case is 264 s, 36 s inside the timeout. Batch 2 keeps 2 free slots, so one more day's link and lookup fit before the next raise.

Cap 11 would also fit, but with no room left.

_From the PR description (author-written)._

- `scripts/check-links.sh`: the batch cap goes from 10 to 12, with the budget comment updated.
