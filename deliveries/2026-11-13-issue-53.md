# docs: add rule 11 (fail closed), mined from Qodo's review history (#53)

**PR:** [#75](https://github.com/lioramilbaum/lioramilbaum.github.io/pull/75) · **Opened:** 2026-11-13 · **Hackathon:** Day 5: [Make your factory self-improve](https://github.com/orgs/qodo-hackathon/discussions/7). [My submission](https://github.com/qodo-hackathon/software-factory-hackathon/discussions/7#discussioncomment-19599476).

## Why

_From the PR description (author-written)._

Day 5 of Qodo's Software Factory hackathon asks the factory to improve its own rules: find an expectation in the review history and turn it into a rule.

Qodo had nothing to suggest for this repo: 0 pending rules, and none of its 56 rules here came from mined patterns (all are imported from AGENTS.md or added by hand). So the coding agent mined the history instead: Qodo's reviews of PRs #25, #34, #45, #46, #54 and #60, including findings Qodo later cleared (they survive in the review comment's edit history). 79 findings in all.

One finding kept coming back, in different code, on five of those six PRs: a check that passed because it could not read its input, or skipped without saying so. Each was fixed on its own. Rules 6 and 9 say "fail closed" for a few named scripts; nothing said it in general, so new scripts weren't covered.

## How

_From the PR description (author-written)._

The agent proposed three candidates, each traced to Qodo findings:

1. **Fail closed** (chosen). "Snapshot errors pass the 404 test" (#25), "Broken submission links pass link checks" (#34), "An unread Qodo layout counts as zero open findings" (#46), "Agent-ready PRs can have failing CI" (#54), "Unusual doc names skip validation" (#60). Covered only case by case by rules 6 and 9 and four Qodo rules.
2. **Evidence names the exact commit it describes** (rejected). Rules 6 and 9 and five Qodo rules already cover it; the one gap left is a bug, tracked in #67.
3. **Docs say only what the code does** (rejected). True of any repo, can't be checked, and Qodo flags it without a rule.

The chosen rule was narrowed before saving: advisory steps may warn instead of failing, as long as they name what they couldn't read; exemptions the rules already name (Renovate, the delivery window) aren't unread inputs; and a failure-path test must check *why* it failed. Like rule 8, it applies to code a PR adds or changes.

Issue #50 (a Qodo copy of rule 10) doesn't count as Day 5: rule 10 came from the Day 3 brief, not from the reviews.

## What

_From the PR description (author-written)._
