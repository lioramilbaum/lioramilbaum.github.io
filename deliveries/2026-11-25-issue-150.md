# fix: read Qodo's skipped-review comment as its own state

**PR:** [#153](https://github.com/lioramilbaum/lioramilbaum.github.io/pull/153) · **Opened:** 2026-11-25

## Why

_From the PR description (author-written)._

Issue #150: since 2026-11-25, Qodo says so when it skips a review. Its comment reads "No findings to report", then "Qodo did not complete this review — the change was judged trivial and was not reviewed — so this is not a clean bill of health". The repo's parser did not know that layout, so the `qodo-findings` status failed with "Qodo's review could not be read". That is the right answer to an unknown layout (AGENTS.md rule 11), but Qodo judges every change under `deliveries/` trivial, so every docs PR went red, starting with #148. Asking Qodo for a review with `/agentic_review` only produced another skipped run.

The older behaviour was worse in a quieter way. Until that day a skipped review still read "Great, no issues found!", and the gate passed it as a clean review (#142, #143, #145). A skipped review is neither clean nor unreadable. It needed its own state.

## How

_From the PR description (author-written)._

- The parser recognises the skipped comment only when two texts are both present, the "No findings to report" heading and Qodo's "did not complete this review" sentence, and the comment lists no finding. Anything else unfamiliar still reads as unknown and fails closed.
- Only Qodo's own review comment is parsed, as before, so a PR author cannot produce the state with a comment or the description.
- The gate then decides by what the PR changes. It reads the PR's file list from GitHub, counting a renamed file by its old path too:
  - only files under `deliveries/`, none of them `deliveries/TEMPLATE.md`, and a complete list: **success**. Those files are generated, and CI's delivery-doc job checks them against the merged head.
  - anything else: **pending**. The head was not reviewed, so the owner decides whether to ask for a review or merge knowing. That includes a PR that changes the template, which the generator builds every doc from and no check reads, and a list that has fewer files than the PR's own changed-file count (GitHub returns at most 3,000).
  - a file list, a file count or a PR head that cannot be read: **error** (rule 11).
  - a head that changed while the gate was checking: nothing is posted, the log says why, and the run the push started decides.
- The same state reaches the three places that read Qodo's review. The delivery doc records `qodo-open=skipped` and says the final review was skipped, where the Delivery doc run used to fail on `unknown`. The docs check accepts it with a warning. The agent run stops and says the head was not reviewed, instead of reporting the PR as ready.
- Every other state (clean, findings, unknown, stale, draft, Renovate) makes the same calls and posts the same statuses as before. Exit codes are unchanged.

_From the PR description (author-written)._

Qodo's first review (of `d26eb7a`) raised three findings, all on the gate's new `skipped` arm. All three were fixed, and none was dismissed.

- "Large code changes can pass as docs-only": valid. GitHub's file list stops at 3,000 files. The gate now compares the number of files listed with the PR's changed-file count, and a mismatch is `pending`.
- "A code head can inherit a docs-only pass": valid. The gate re-reads the PR head as its last call before posting, and posts nothing when the head changed.
- "Unreviewed template edits get a green status": valid. A PR that changes `deliveries/TEMPLATE.md`, as a current or a previous filename, is `pending`. Criteria 3 and 4 of #150 were reworded with the owner's approval to say so.

## Limitations

_From the PR description (author-written)._

- The real status post and the real file-list call run only in the Qodo findings workflow, from main, so they run for the first time after this merges. The tests use a stub in place of `gh`.
- Criterion 9 names #148, which was merged before this PR was opened. The same check is made on the next open docs PR instead (the one that carries this PR's delivery doc), and the run is linked on #150.
- The match is on Qodo's exact wording. If Qodo rewords the sentence or the heading, the comment reads as unknown again and the gate fails closed, as it did on #148.
- A comment that lists findings in a layout the parser does not know, and also carries both skip texts, would read as skipped. Qodo does not write both today.
- On a code PR, `pending` is advice: no ruleset on `main` requires the status, so GitHub still allows the merge.
