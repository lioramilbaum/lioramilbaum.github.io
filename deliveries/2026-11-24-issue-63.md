# fix: test that check-delivery.sh skips a doc a docs PR deletes

**PR:** [#137](https://github.com/lioramilbaum/lioramilbaum.github.io/pull/137) · **Opened:** 2026-11-24 · **Hackathon:** [Day 14: Turn your quality gate into a workflow](https://github.com/orgs/qodo-hackathon/discussions/16): this is the PR outside the guarded path (`.github/**`). It changes only `scripts/test-delivery.sh`.

## Why

_From the PR description (author-written)._

Issue #63: `scripts/check-delivery.sh` checks each delivery doc a docs PR adds or changes. A doc the PR deletes is in the list of changed files too, and one line skips it: `git cat-file -e "HEAD:$doc" 2>/dev/null || continue`. No test committed a deletion, so CI never ran that line (AGENTS.md rule 8). If the line were lost in a later change, a docs PR that removes a doc would fail the check with a git error, and no test would say why.

## How

_From the PR description (author-written)._

- Two new cases in `scripts/test-delivery.sh` build a small repository whose last commit deletes a delivery doc, then run the real `scripts/check-delivery.sh` on it.
- Each case asserts why the check passed (AGENTS.md rule 11): the exit code and the exact `docs PR: N delivery doc(s) checked` line. A check that skipped, because it saw a code PR or a closed delivery window, prints a different line and fails the case.
- `scripts/check-delivery.sh` is unchanged. The cases use the test file's existing helpers and its pinned clock.

## What

_From the PR description (author-written)._

- `scripts/test-delivery.sh`, 36 added lines, two cases after `shot`:
  - `del`: a docs PR that only deletes a doc. The check exits 0 and prints `docs PR: 0 delivery doc(s) checked`. Its log has no `fatal:`, no `no delivery metadata` and no mention of the deleted doc.
  - `deladd`: a docs PR that deletes one doc and adds a generated one. The check exits 0, prints `docs PR: 1 delivery doc(s) checked` and `<doc>: ok`, and never mentions the deleted doc.
